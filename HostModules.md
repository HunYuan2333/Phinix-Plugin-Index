# Host module profiles

[中文](HostModules.zh-CN.md). `host-module-profiles.json` is maintainer-owned configuration generated by reading module attributes from a built main package, without loading plugin code. Publication combines the discovered host graph with the selected package graph. The validator contains no named plugin/module exemptions.

A profile applies only when it covers every selected package's declared Phinix range. Missing configuration grants no host capabilities. Unknown modules, cycles, shadowed host assemblies/modules, duplicate/unknown fields and ambiguous matching profiles are rejected. Player installation/startup still checks actual host modules, enabled state, assemblies and compatibility. This configuration is not an author declaration or a substitute for actual game availability.

Regenerate from the main repository after building its clean output:

```sh
dotnet Extensions/PluginStore/Tools/ManagedPackageTool/bin/Release/net10.0/ManagedPackageTool.dll --export-host-profile Output/phinix-rework/Common/Extensions --phinix-range '>=0.9.7 <1.0.0' --output /tmp/phinix-host-profile-new.json
```

Review the deployment range and discovered graph, then replace this repository's configuration through a normal reviewed code PR. Every assembly has a SHA-256 provenance value; the export reads only immediate DLLs with input limits and never executes constructors or attributes. The supplied development profile was generated from the 2026-10-06 clean main output (8 assemblies/5 modules). Re-export for a changed host product; do not add business IDs to validator branches or delete a plugin's real module dependencies to make publication pass.
